# BridgeTournament

Telegram-бот для проведения бриджевых турниров. Для разработки нужен JDK 25.
Gradle устанавливать отдельно не нужно: используйте `./gradlew` (Windows — `gradlew.bat`).

## Настройка

Скопируйте `.env.example` в `.env` и укажите токен своего бота и пароль PostgreSQL.
Файл `.env` не попадает в Git и в контекст сборки Docker.

```sh
cp .env.example .env
```

## Запуск в Docker

```sh
docker compose up --build
```

Образ приложения собирает JAR из исходников на JDK 25 и запускает его на JRE 25.
Предварительная локальная сборка не нужна. Приложение запускается после успешной
проверки готовности PostgreSQL. Внутри Compose адрес БД автоматически задаётся
как `postgres:5432`; с компьютера база доступна по адресу `localhost:5433`.

### Работа с VPN

В Compose явно задана подсеть `172.30.251.0/24`. Это позволяет создавать сеть
при включённом VPN, широкие маршруты которого могут мешать Docker автоматически
выбрать диапазон адресов и вызывать ошибку
`all predefined address pools have been fully subnetted`.

Если эта подсеть занята другой локальной сетью или Docker-проектом, задайте
свободную подсеть через `DOCKER_SUBNET` в `.env`. При изменении подсети уже
созданную сеть проекта нужно пересоздать:

```sh
docker compose down
docker compose up -d --wait postgres
```

Команда `down` без `-v` сохраняет том с данными PostgreSQL. После неё при работе
полностью в Docker снова запустите приложение командой `docker compose up -d --build`.
Настройка подсети решает создание сети; доступ контейнеров в интернет также
зависит от маршрутизации и правил VPN-клиента.

## Локальная разработка

Запустите только базу:

```sh
docker compose up -d --wait postgres
```

Gradle и Spring Boot сами не читают `.env`. Для Bash/Zsh экспортируйте переменные
из своего `.env`, затем запустите приложение:

```sh
set -a
source .env
set +a
./gradlew bootRun
```

В IDE выберите JDK 25 для проекта и Gradle, а переменные из `.env` добавьте
в конфигурацию запуска. Флаг `--enable-preview` больше не нужен.
Используйте отдельного бота для разработки и запускайте только один экземпляр
приложения с одним токеном.

### Тестовые пользователи

После применения миграций можно добавить `test_user_1` — `test_user_10`:

```sh
docker compose exec -T postgres sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < scripts/seed-test-users.sql
```

Скрипт можно запускать повторно: существующие записи сохраняются, дубли не
создаются. Он добавляет профили и связи с провайдером Telegram, поэтому
пользователи доступны для выбора и поиска по username. Их внешние ID имеют
вид `seed:test_user_1`: это тестовые записи, у которых нет настоящего Telegram-чата.

## Управление турниром в Telegram

Все методы `TournamentService` доступны через команды бота:

| Команда | Действие |
| --- | --- |
| `/create` | Создать турнир: выбрать IMP/MP, число сдач, название и число туров |
| `/addtd` | Выбрать и добавить судью |
| `/addplayer` | Записаться без пары, указав username создателя или судьи турнира |
| `/addpair` | Записать себя и партнёра, указав username судьи, затем партнёра |
| `/addtournamentpair` | Судье добавить в свой турнир пару по username первого и второго игрока |
| `/removeplayer` | Судье удалить из своего турнира участника или его пару по одному username |
| `/tds` | Показать судей турнира |
| `/players` | Показать пары и игроков без пары |
| `/starttournament` | Подтвердить запуск турнира и сформировать расписание |
| `/addtournamentboard` | Добавить существующую сдачу по идентификатору, полученному через `/addboard` |
| `/addtournamententry` | Игроку ввести результат сдачи текущего тура по номеру |
| `/tournamentresults` | Показать текущие места и очки пар турнира |

Команды управления работают с текущим турниром пользователя как судьи.
`/addplayer` и `/addpair` вызывает сам игрок: турнир выбирается по текущему
турниру указанного судьи. Создание турнира делает его текущим для создателя;
добавление судьи — для нового судьи.
Перед запуском в системе должен быть подходящий регламент движения пар
(его можно загрузить через `/addmovement`). При запуске игроки без пары
объединяются автоматически; при нечётном количестве один игрок не попадёт
в расписание, о чём бот предупреждает перед подтверждением.

В `/addtd` новый судья выбирается кнопками из пользователей системы, с
переключением страниц; уже добавленные судьи исключаются из списка.
В `/addplayer` и `/addpair` username вводится с `@` или без него, без учёта
регистра. Судья и партнёр должны ранее обратиться к боту; если username
изменился, им нужно обратиться к боту ещё раз, чтобы обновить данные.
При неизвестном или неоднозначном username бот предлагает повторить ввод.

Username внешнего аккаунта хранится в `external_accounts` и уникален внутри
провайдера без учёта регистра и начального `@`. Отсутствие username допускается
у нескольких аккаунтов. Поиск судьи и партнёра использует только аккаунты
провайдера Telegram; старый профиль без связи с провайдером не участвует в поиске.
При переходе username к другому Telegram ID устаревший username освобождается,
а прежний `userId` и его результаты сохраняются. Совпадение username не объединяет
пользователей автоматически.

Такая же уникальность закреплена непосредственно в `users` по полям
`registration_provider` и username. Старые профили считаются зарегистрированными
через Telegram; при миграции username у дублей сохраняется за привязанным внешним
аккаунтом, а у устаревших профилей сбрасывается в `NULL`. Их UUID и результаты
сохраняются. При обновлении профиля провайдер регистрации сохраняется.

Инициатор определяется по Telegram ID и внутреннему `userId`, а username
нужен для поиска другого пользователя и отображения. Свой username инициатору
иметь не обязательно. Профиль можно заполнить через `/register`.
Внутренний `userId` генерируется Hibernate как UUID при создании пользователя;
числовой Telegram ID хранится отдельно в `external_accounts.external_id`.
`/addpair` всегда записывает инициатора первым игроком; участники, ранее
записавшиеся без пары, после объединения исчезнут из списка «Без пары».
Повторная запись участника и составление пары с самим собой не допускаются.

`/addtournamentpair` и `/removeplayer` доступны создателю или судье текущего
турнира. Добавление пары и удаление участников разрешены только до старта.
При `/removeplayer` игрок без пары удаляется один, а для игрока в паре удаляется
вся пара. Их текущий турнир как игроков очищается только при совпадении с этим
турниром; роль судьи сохраняется. Самостоятельной команды выхода для игроков нет.

`getTds` возвращает `List<UserDto>`. В чате судьи выводятся нумерованным списком
в формате `Имя Фамилия (@username)`; если имя или username не заполнены,
используются доступные данные. Длинные списки разбиваются на сообщения.

В `/addtournamententry` бот показывает текущий тур, стол, соперников и номера
незаписанных сдач. После выбора номера используются те же состояния ввода
контракта, атаки, результата и подтверждения, что в `/addentry`. Тип подсчёта
берётся из турнира автоматически. После подтверждения приходит HTML-протокол
сдачи. Следующий тур становится доступен после записи всех сдач текущей встречи.
Результат записывается от имени игрока, отправившего `/addtournamententry`:
в сервис передаётся его внутренний `userId`. Чужие сообщения и нажатия кнопок
не изменяют его сессию. Игрок может исправлять только собственную запись;
судья без участия в турнире как игрок вводить результаты за других пока не может.

`/tournamentresults` показывает пары, места и очки: сумму IMP или средний MP в
процентах. При равных очках место совпадает. Для игрока используется его текущий
игровой турнир; если его нет, используется текущий турнир в роли судьи.
Результаты пересчитываются по введённым сдачам этого турнира. Для MP при одном
результате на сдаче временно используется 50%; при появлении других результатов
процент пересчитывается. `/addentry` также поддерживает IMP и MP.
MP сравнивает результаты одной сдачи: за каждый худший результат начисляются
две единицы, за равный — одна, затем результат переводится в процент от максимума.
Основа расчёта — [закон 78A WBF](https://www.worldbridge.org/wp-content/uploads/2017/03/2017LawsofDuplicateBridge-paginated.pdf).

`/cancel` завершает текущий диалог. Новая команда также сбрасывает предыдущий
диалог. Все команды перечислены в `/help` и меню бота. В группах поддерживается
форма `/команда@ИмяБота`; `TELEGRAM_BOT_USERNAME` должен соответствовать
имени вашего бота без `@`. Команды, адресованные другому боту, игнорируются.

## Проверки

```sh
./gradlew test             # Модульные тесты, без Docker
./gradlew check            # Все тесты; нужен работающий Docker
./gradlew clean build      # Все тесты и сборка JAR
./gradlew bootJar          # Только сборка build/libs/app.jar
```

Интеграционные тесты входят в `check` и `build`, создают отдельную БД через
Testcontainers и не требуют `.env` или токена Telegram. Проверка запуска
подменяет Telegram-бота тестовым объектом и проверяет загрузку приложения,
миграции БД и OpenAPI. Сборка Docker-образа выполняет только `bootJar`;
перед публикацией образа запускайте `./gradlew check` отдельно.

Версии PostgreSQL сохранены: 16 в Compose и 15 в интеграционных тестах.

## Загрузка данных из БД

Для всех связей JPA-сущностей явно задан `FetchType.EAGER`: репозитории возвращают
полностью заполненные DTO, которые можно использовать после закрытия сессии
Hibernate. При добавлении новых связей сохраняйте эту настройку. Сам маппинг
MapStruct не открывает сессию и не меняет стратегию загрузки.

`EAGER` не гарантирует один SQL-запрос. Для списков пар и результатов используются
`EntityGraph`, для расписания — `JOIN FETCH`, включая профили игроков и сдачи.
Поиск следующей встречи ограничивается на стороне БД, после чего её сдачи
загружаются отдельно: коллекция не присоединяется к запросу с пагинацией.
Результаты турнира читаются двумя запросами: идентификаторы результатов,
затем связанные данные. Для новых запросов нужно также задавать подходящий
план загрузки, чтобы избежать N+1.

`DetachedTournamentReadTests` проверяет чтение без общей тестовой транзакции
и количество SQL-запросов. Это воспроизводит условия Telegram-обработчиков:
открытая сессия теста не должна скрывать ошибки ленивой загрузки.
